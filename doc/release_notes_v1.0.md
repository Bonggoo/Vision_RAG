## TechNote 는 무엇인가

산업용 매뉴얼(PDF)을 **사람이 찾는 방식 그대로** 뒤지는 문서 질의 시스템이다.

일반적인 RAG 는 문서를 잘게 쪼개(chunking) 벡터 DB 에 넣고 유사도로 꺼내온다. TechNote 는
**벡터 DB 를 쓰지 않는다.** 대신 AI 가 사람처럼 움직인다 — 목차를 먼저 읽고, 해당 장으로
건너뛰고, 그 페이지를 **이미지 그대로 보고** 답한다.

이 선택의 이유는 산업 매뉴얼의 정보가 대부분 **표·도면·배선도·알람 코드표**에 들어 있기
때문이다. 텍스트로 쪼개는 순간 표의 행과 열 관계가 끊기고 도면은 통째로 사라진다.
페이지를 이미지로 보내면 레이아웃이 100% 보존된다.

**핵심 특성**
- **Vectorless** — 임베딩·청킹·벡터 DB 인프라가 없다. 문서를 올리면 목차만 뽑아 두면 끝
- **Zero Context Loss** — 답변 근거 페이지를 원본 레이아웃 그대로 Vision 모델에 전달
- **3-Phase 추론** — 문서 선택 → 페이지 특정 → Vision 분석의 3단 탐색

## 아키텍처 한눈에

```
질문
 └─ Phase 0+1  문서 선택 + 목차 계층 파악        (Flash-Lite, 텍스트만)
     └─ Phase 2  키워드 매칭으로 정확한 섹션 특정  (텍스트 검색)
         └─ Phase 3  해당 페이지만 미니 PDF 로 추출 → Vision 분석 → 답변
```

- **백엔드**: FastAPI + LangChain(`ChatGoogleGenerativeAI`) + Google Cloud Storage
- **프론트엔드**: Next.js(App Router) + Zustand + Tailwind, PWA
- **배포**: 통합 오리진 — 프론트 정적 export 를 백엔드 이미지에 담아 Cloud Run 단일 서비스로
  서빙한다. `/` 는 프론트, `/api/*` 는 백엔드. iOS 로그인 세션 유지 문제를 이 구조로 해결했다
- **인증**: Google OAuth → 자체 JWT(access 30분 + refresh 30일, HttpOnly 쿠키)

## v1.0 에서 마지막으로 들어간 변경 (2026-08-23)

### 참조 페이지 원본 PDF 보기
답변 하단의 참조 썸네일을 펼치면 **"원본 PDF N쪽 열기"** 버튼이 나온다. 새 탭에서 원본
PDF 가 해당 페이지부터 열려 확대·텍스트 검색·드래그가 가능하다.

썸네일(150 DPI PNG)은 즉시 뜨는 미리보기로 그대로 두고 원본 경로를 **추가**했다.
용도가 다르기 때문이다 — 빠른 확인은 썸네일, 정독은 원본.

- 신규 `GET /documents/{id}/view-url` — `inline` disposition Signed URL
  (`attachment` 면 브라우저가 파일을 저장해 버려 `#page=N` 이 무시된다. 기존 다운로드
  경로는 `attachment` 를 유지해야 해서 엔드포인트를 분리했다)

### 요청 속도 제한 (보안 감사 H-1)
Gemini 과금 폭주와 Cloud Run 동시성 고갈을 막는 제한을 넣었다.

| 대상 | 한도 |
|---|---|
| 채팅 (`/chat/*`) | 20회/분, 300회/시 |
| 업로드·재분류 | 10회/분, 100회/시 |
| 로그인·토큰 갱신 | 20회/분, 200회/시 |
| 그 외 API | 120회/분 |

식별자는 검증된 JWT 이메일, 없으면 IP. 정적 프론트와 헬스체크는 대상이 아니다.
초과 시 429 와 함께 몇 초 뒤 재시도하면 되는지 안내한다.

### 리프레시 토큰 서버 측 폐기 (보안 감사 H-3)
기존에는 로그아웃이 브라우저 쿠키만 지웠다. 토큰 자체는 최대 30일 살아 있어서, 토큰이
유출된 상태라면 **로그아웃해도 소용이 없었다.**

이제 로그아웃하면 서버가 그 계정의 폐기 시각을 올려 **발급돼 있던 모든 리프레시 토큰이
즉시 무효화**된다. 재로그인은 정상 동작한다.

  2026-08-16 에 불용어 목록으로 완화해 이후 4회 연속 정상이지만, 목록에 없는 기능어는
  여전히 승격될 수 있다. → [open_quality_issues.md](./open_quality_issues.md)

- **속도 제한은 인스턴스 단위** — Cloud Run 인스턴스마다 카운터가 독립이라 전역 정확도가
  없다. 단일 클라이언트 폭주 차단이 목적이므로 의도된 트레이드오프다.

- **리프레시 토큰 rotation 재사용 탐지 미구현** — "로그아웃 시 전체 폐기"까지만 구현했다.
  회전된 옛 토큰의 재사용을 탐지해 토큰 패밀리를 끊는 단계는 v2 로 미뤘다.

- **Cloud Tasks 미설정** — 업로드 후 분석이 Cloud Run 인스턴스 내 백그라운드 태스크로
  돈다. 인스턴스가 회수되면 문서가 `analyzing` 상태로 멈출 수 있다. 동시 업로드가 늘면
  설정이 필요하다. → [v1.0_release_checklist.md](./v1.0_release_checklist.md) 1-2 절

## 품질 측정에 대한 정직한 기록

`backend/evals/` 에 골든셋 기반 자동 평가 하네스가 있고, routing / document / recall / pages
4개 축으로 채점한다. 다만 **v1.0 시점의 데이터셋은 20문항이라 측정 해상도가 낮다.**

1문항이 5%p 인데 실행 간 표준편차가 ±15%p 로, **4문항 미만의 품질 변화는 원리적으로
관측되지 않는다.** 따라서 이 하네스의 점수는 "좋아졌다"를 증명하는 데 쓸 수 없고, 큰
회귀를 잡는 용도로만 유효하다. 자동 실행은 v1.0 과 함께 중단했고, 검색·라우팅 로직을
건드릴 때만 수동으로 돌린다.

의미 있는 품질 개선을 하려면 **데이터셋을 100문항 규모로 키우는 것이 선행 조건**이다.
자세한 근거는 [v1.0_release_checklist.md](./v1.0_release_checklist.md) 에 있다.
