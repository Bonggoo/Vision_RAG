# 매뉴얼 탐색 스킬화 실험 — 폐기 기록

작성일: 2026-10-26 · 대상: Vision_RAG (TechNote)
코드 보관: 브랜치 `claude/manual-navigator-skill` (커밋 `57f6d03`). **머지하지 않고, 지우지도 않는다.**
보관용 태그도 만들려 했으나 작업 환경에서 태그 푸시가 막혀 브랜치만 남겼다.

---

## 요약

TechNote의 목차 기반 탐색 방식을 서버 없이 Claude Code 등에서 쓰는 Agent Skill로 만들어
판매하는 방안을 검토했다. 스킬을 만들고 스킬 사용/미사용을 A/B로 비교한 결과
**정답률에 차이가 없어 폐기했다.**

| 항목 | 스킬 사용 | 스킬 없음 |
|---|---:|---:|
| 채점 항목 통과 | 58/58 | 58/58 |
| 토큰 (평균) | 88,284 | 92,028 |
| 실행마다 토큰이 달라지는 폭 (표준편차) | 7,630 | 15,802 |
| 시간 (평균) | 143초 | 137초 |
| 도구 호출 (평균) | 15.9 | 17.7 |
| 블라인드 채점자가 지적한 출처·표기 문제 | 0건 | 5건 |

최상위 모델은 PDF를 그대로 받아도 매뉴얼을 찾고, 페이지를 찾고, 표와 그림까지 읽어 이번
질문을 모두 풀었다. 스킬의 효과는 출처 표기 규율과 실행 간 일관성 정도로 작게만 보였다.

---

## 1. 배경과 목표

- 서버(FastAPI·GCS·Gemini)와 인증·프론트엔드를 모두 빼고, 문서 선택·페이지 선택·이미지 읽기는
  스킬을 쓰는 에이전트가 직접 하게 한다. 스크립트는 PDF 처리만 맡는다.
- `prompts.py`의 판단 규칙(제어 계층, 되묻기, 목록에 없는 브랜드, 원문 페이지 인용, 첨부 페이지
  밖 추측 금지)만 스킬 문서로 옮긴다.
- 스킬 거래 사이트 판매를 염두에 뒀다.

## 2. 만든 것

브랜치 `claude/manual-navigator-skill`의 `skill/` 아래에 있다.

| 파일 | 내용 |
|---|---|
| `manual-navigator/SKILL.md` | 작업 순서와 판단 규칙 (영어 본문, 한/영 호출 조건) |
| `manual-navigator/scripts/manual.py` | `toc`(폴더 목록·목차 출력·`--write`·`--undo`), `find`(코드 표기 정규화 검색). pypdf만 사용 |
| `manual-navigator/references/build-toc.md` | 목차 없는·부실한·스캔 매뉴얼의 목차 생성 절차 |
| `manual-navigator/evals/` | 가상 매뉴얼 생성기 + 평가 문항 10개 (`claude plugin eval` 형식) |
| `tests/test_manual.py` | 단위 테스트 29개 |

설계 과정에서 정한 것:
- 처음 계획한 6개 명령(index·toc·text·grep·render·breadcrumb)과 `index.json` 캐시는 2개 명령으로
  줄였다. 페이지 읽기와 렌더링은 에이전트가 원래 할 수 있어서다.
- PDF 라이브러리는 PyMuPDF 대신 pypdf를 썼다. PyMuPDF는 AGPL이라 유료 배포와 충돌할 수 있다.
- 에이전트가 만든 목차는 별도 파일 대신 PDF 북마크로 저장한다. 원본 뒤에 덧붙이는 증분 저장이라
  원본 바이트가 그대로 남고, 덧붙인 부분을 잘라내면 원본과 바이트 단위로 같아진다.

## 3. 실험 설계

- **자료**: 가상 브랜드(Acme·Globex·Initech) 매뉴얼 6권, 총 572페이지. 실제 제조사 자료나
  사내 자료는 쓰지 않았다. 브랜드를 가상으로 한 이유는 모델이 기억으로 답하지 못하게 하기 위해서다.
  - 북마크가 충실한 매뉴얼, 북마크 없이 인쇄 목차만 있는 설치 가이드, 북마크가 3개뿐인 매뉴얼,
    텍스트 층이 없는 스캔본
  - 같은 `AL.21`이 기종마다 다른 뜻(AS100 과부하 2 / AS200 엔코더 통신 이상)
  - 서보 매뉴얼에는 없고 상위 모션컨트롤러 매뉴얼에만 있는 에러 코드 2051
  - 장-페이지 형식 인쇄 번호("8-6"), 이미지로만 있는 핀 배치표
- **문항 10개**: 알람 원인, 상위 장비 코드, 모델 미지정, 폴더에 없는 브랜드, 스캔본 고장 코드,
  목차 없는 문서의 배선, 이미지 속 핀, 북마크 부실 문서의 파라미터, 원점복귀 방식, 인쇄 페이지 번호.
- **실행**: 같은 모델로 스킬 사용/미사용을 문항마다 새 세션에서 1번씩, 총 20회. 각 실행은 매뉴얼
  사본을 따로 받았다.
- **채점**: 답변을 무작위 ID로 섞어 어느 쪽인지 가린 뒤 별도 채점자가 문항별 기준(사실·인용 페이지)으로 채점했다.

## 4. 결과

- 20개 답변이 모두 채점 기준을 통과했다. 스킬 없는 쪽도 스캔본을 이미지로 읽고, 인쇄 목차로
  페이지를 찾고, "8-6쪽"을 PDF 106페이지로 바꾸고, 2051을 상위 컨트롤러 코드로 판단하고,
  없는 브랜드는 없다고 답했다.
- 토큰은 스킬 쪽이 4% 적었고 실행 간 편차는 절반이었다. 시간은 5% 길었다. 세션마다 고정 비용이
  커서 차이가 희석된 값이다.
- 채점자가 기준 밖에서 지적한 문제 5건은 모두 스킬 없는 쪽이었다. 페이지 근거 없이 "매뉴얼에
  있다"고 쓴 문장 2건, 자기 추론을 표시하지 않은 문장 1건, 인쇄 번호를 PDF 페이지처럼 쓴 것 1건,
  사용자가 말하지 않은 코드를 언급한 것 1건이다. 스킬의 판단 규칙이 겨냥한 부분과 맞지만 표본이 작다.
- 스킬 쪽은 목차 없는 매뉴얼 3권에서 목차를 만들고 PDF에 저장하자고 제안했다. 저장한 목차가
  다음 질문 비용을 얼마나 줄이는지는 질문 1회짜리 실험이라 측정하지 못했다.

**한계**: 합성 매뉴얼(반복 문장이 많음), 문항 10개, 조건별 1회, 최상위 모델만 사용.

## 5. 폐기 이유

1. **정확도 이득이 없다.** "더 정확하다"는 판매 근거를 만들 수 없다.
2. **복제가 쉽다.** 스킬은 평문 폴더라 한 번 팔리면 재배포를 막을 수 없다.
3. **구매자와 실사용자가 다르다.** 스킬 거래 사이트의 구매자는 개발자인데, 이 문제를 겪는 사람은
   현장 정비 엔지니어이고 이들은 Claude Code를 거의 쓰지 않는다.
4. **무료 대안과 겹친다.** 에이전트의 기본 PDF 읽기, 공식 pdf 스킬, 같은 개념의 오픈소스(PageIndex)가 있다.

## 6. TechNote에 가져올 만한 발견

아래는 스킬을 만들며 기존 코드를 읽다 확인한 것이다. **아직 고치지 않았다.**

1. **장-페이지 번호 오변환** — `backend/app/services/agentic/toc.py:15` `normalize_page`는
   "3-32"를 32로 바꾼다. 32는 3장 안의 쪽 번호라 PDF 페이지로는 틀리다. 목차 페이지 추출 프롬프트가
   절대 번호로 바꿀 수 없으면 "3-32"를 문자열로 그대로 적으라고 하므로
   (`backend/app/services/agent_service.py:216`) 실제로 이 경로를 탈 수 있다.
2. **인쇄 번호와 PDF 번호의 차이를 검증하지 않음** — Gemini는 목차 페이지만 보고 절대 페이지를
   추정한다. 표지·서문만큼 어긋나도 확인하는 단계가 없다. 스킬에서는 항목 2~3개의 실제 페이지에
   제목이 있는지 확인하게 했다(브랜치의 `references/build-toc.md` 3절). 실제 문서에서 얼마나
   어긋나는지는 측정하지 않았다.
3. **깨진 북마크 통과** — `backend/app/services/pdf_service.py:102` `is_toc_meaningful`은 하위 레벨
   항목이 하나만 있어도 통과한다. 모든 북마크가 같은 페이지를 가리키거나, 링크가 깨졌거나, 문서
   앞부분에서 끝나는 경우를 걸러내지 못한다. 스킬의 `assess_toc`에 검사 규칙이 있다.
4. **작동하지 않는 상한** — `backend/app/services/agentic/llm_steps.py:36`
   `PHASE2_MAX_SCAN_PAGES = 200`은 호출부가 항상 50페이지로 먼저 자르기 때문에 적용되지 않는다.
5. **알람 코드 매칭 규칙** — `AL.21`로 `AL21`·`AL-21`·하위 코드 `AL.21.1`은 찾고 `AL.210`은
   거르는 규칙과 테스트가 스킬의 `term_pattern`에 있다. Phase 2 키워드 매칭에 옮겨 쓸 수 있다.
6. **가상 매뉴얼 생성기** — 브랜치의 `skill/manual-navigator/evals/make_samples.py`. 사내 문서 없이
   돌릴 수 있는 평가 자료라 `backend/evals`에서도 쓸 수 있다. 정답 페이지를 JSON으로 함께 낸다.
7. **pypdf 증분 저장 버그** — pypdf 6.17에서 같은 파일을 두 번째로 증분 저장하면 객체 번호가 겹쳐
   파일이 깨진다. 새 객체 번호를 trailer의 `/Size` 뒤에서 시작하게 우회했다(브랜치의
   `write_bookmarks`). PDF에 목차를 써 넣는 기능을 서버에 넣는다면 필요하다.

**전략적 시사점**: 최상위 모델에 PDF를 그대로 주면 이 정도 질문은 풀린다. TechNote의 강점은
정확도 자체보다 비용(Flash-Lite), 현장 사용성(모바일·사진 질문), 업로드 시 한 번 만들어 두는
목차와 메타데이터 쪽에 있다.

## 7. 다시 검토할 조건

- 더 작고 저렴한 모델에서 스킬 유무의 차이가 크게 나올 때
- 같은 매뉴얼에 두 번째로 질문할 때 저장한 목차의 비용 절감 효과가 확인될 때
- 사용자가 "목차 없는 스캔 매뉴얼에 북마크 만들기"를 따로 원할 때
